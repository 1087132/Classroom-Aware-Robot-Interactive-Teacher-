# CAT - Classroom-Aware Interactive Robot Teacher

Working software prototype of the capstone project **"Classroom-Aware Interactive
Robot Teacher"** (Abu Dhabi University). It runs the full classroom ecosystem on a
local network - no cloud required (privacy by design).

## What it does

| View | URL | Purpose |
|---|---|---|
| Landing + QR | `http://localhost:8000/` | Links to all views, QR code for students |
| Teacher dashboard | `http://localhost:8000/teacher` | Start/pause/resume/end lessons, live engagement, robot controls |
| Student app | `http://<lan-ip>:8000/student` | Join with name + seat, answer MCQs, ask the robot questions |
| Robot face | `http://localhost:8000/robot` | Animated expressions + text-to-speech voice |
| Projector view | `http://localhost:8000/projector` | Questions, timers, results and leaderboard on the big screen |
| Student tracking | `http://localhost:8000/tracking` | Teacher-only: live per-student tracking, alerts, attendance + session history |

### Implemented capstone features

- **Lesson engine** - two lesson scripts (Math Puzzle Adventure, Solar System
  Science Quiz) with content slides, timed MCQs, explanations and a double-points
  mini-game (quick-fire round).
- **Engagement analytics** - the paper's score model
  `Score = 1/4(A) + 1/4(P) + 1/4(Q) + 1/4(S)` (Attention, Participation frequency,
  Quiz performance, Speaking), recomputed **every 5 seconds**, with a live class
  timeline chart and per-student/session history on the tracking page.
- **Perception system** - simulation mode: simulated per-student attention
  (gaze/head-pose proxy) and **sound-source localization** (azimuth + classroom
  zone). **Camera mode: real face + GAZE detection** (OpenCV Haar cascades,
  all local): frontal face with 2 eyes = *focused*, 1 eye = *partial*, no eyes
  = *down* (reading/phone), profile face = *away* (head turned). The tracking
  page shows a live annotated feed (gaze-colored boxes + zone grid); each seat
  column's gaze state drives its students' attention scores. Toggle with
  "Start camera monitoring" on `/tracking`. Frames are never stored.
- **Constrained LLM / NLU with a local offline model** - a retrieval layer
  decides on-topic vs off-topic (off-topic is politely refused and never
  reaches the model). On-topic answers are generated by a **local LLM
  (Ollama + llama3.2:1b, ~1.3 GB stored in `~/.ollama/models`)** constrained to
  the teacher-approved lesson fact - after the one-time download it runs with
  **no internet connection**. If the model isn't running, answers fall back to
  the knowledge base (still offline). The dashboard's Ask-CAT card shows which
  engine is active; `GET /api/llm/status` reports it too.

  Setup (already done on this machine): `brew install ollama`, then
  `ollama pull llama3.2:1b`. `run.sh` auto-starts the Ollama server. Use a
  different downloaded model with `OLLAMA_MODEL=<name> ./run.sh`.
- **LLM connected to MCQs and answers** - three integrations, all offline:
  1. *Personalized answer feedback*: when a student answers an MCQ, the LLM
     writes one kind sentence about THEIR answer (right or wrong, grounded in
     the approved explanation) and pushes it live to their device.
  2. *Class insight*: when a question closes, the LLM comments on the answer
     distribution and the robot speaks it (speech is queued, never cut off).
  3. *AI-generated questions*: the "AI question" button drafts a brand-new MCQ
     from the lesson knowledge base (model names the correct answer explicitly;
     options are shuffled locally; quality-gated with retries). **The teacher
     previews and approves it before it goes live.** Tip: `ollama pull
     llama3.2:3b` gives noticeably better questions than the 1b model.
- **Teacher-triggered interventions** - from the roster the teacher can have the
  robot call on a student by number or push them an easier question at any time.
- **Lesson upload** - teachers add their own lessons from local disk (JSON file,
  validated with clear errors; a downloadable template is provided). Uploaded
  lessons are stored in `backend/lessons/` and survive restarts.
- **Textbook PDF -> lesson (LLM MCQ generation)** - the "Textbook PDF -> lesson"
  button turns a whole textbook into a lesson, fully offline: the PDF is
  extracted locally (pypdf), workbook noise is stripped, teachable passages
  become the ask-CAT **knowledge base**, and the local LLM drafts MCQs through a
  two-step pipeline (distill a self-contained fact -> write the question) with
  strict quality gates (answers must be grounded in the book, no duplicate or
  workbook-reference options, numeric sanity checks). Example included:
  `grade3_math` was built from *Mathematics Grade 3 - Part 1 PUPIL (2017)* -
  ask-CAT then answers from the textbook too. Best with `llama3.2:3b` (default
  when downloaded); always preview the draft questions before class. CLI:
  `python -m backend.textbook "<pdf>" --title "..." --id my_lesson --questions 8`.
- **Lesson scheduling & timing** - schedule a lesson for a clock time (HH:MM);
  the robot starts it automatically. Optional **auto-advance** lets the robot
  pace the whole lesson hands-free (greeting ~10 s, content slides ~35 s,
  reviews ~10 s, questions use their own timers), and an optional **mini-game
  moment** launches the quick-fire round N minutes into the lesson (the paper's
  "mid / last third / end" quiz timing). The teacher can pause or override at
  any point.
- **Automated face control** - the robot's expression follows the live class
  engagement score (happy >=80, neutral 60-79, thinking 45-59, concerned <45),
  with encouraging voice nudges when the class drifts and praise when it excels.
  Lesson events (greeting, questions, reveals) still take priority, a manual
  expression from the teacher holds auto mode for 30 s, and the dashboard has an
  auto-face ON/OFF toggle.
- **Robot face + voice** - animated expressions (happy, curious, thinking,
  concerned, excited...) with browser text-to-speech (speech is queued so
  sentences never cut each other off).
- **Speech-to-text + interaction detection** - students tap the mic button on
  their device and speak: the transcript is recorded to the local database and
  classified as a **question / comment (interacting with the teacher)**, a
  **spoken answer** to the open MCQ (matched against its options), or
  **off-topic chatter**. The robot face page has a *classroom mic* toggle that
  continuously transcribes what the class says (the robot's mic array role).
  Real speech feeds the S (speaking) component of the engagement score and
  pauses the simulated audio events. The dashboard shows a live "Speech log
  (STT)" card with interaction badges. Students can also toggle text-to-speech
  so CAT reads its answers aloud. Note: browser speech recognition requires
  localhost or HTTPS (works in the same-machine demo; phones over plain
  http:// hide the mic button).
- **Local database** - SQLite stores lessons, sessions, students, responses,
  engagement samples, event log, and the ask-the-robot log.
- **REST APIs + WebSockets** - live updates to every connected screen.
- **Student tracking (teacher-only)** - `/tracking` combines a live class view
  (per-student sparklines, A/P/Q/S bars, low-engagement alerts below 45) with a
  persistent student registry: attendance %, cross-session engagement trends,
  quiz accuracy, per-student profiles and past-session drill-downs.
- **Anonymous student identity** - no names are stored anywhere. Every person is
  an auto-numbered **Student N** with a unique ID (e.g. `S-007`), either
  pre-registered by the teacher on the tracking page or auto-issued on first
  join. Returning students join with their ID; it is shown on their device and
  remembered by their browser. Legacy databases are anonymized on startup.

### Teacher login

The teacher dashboard, tracking page and all teacher APIs (lesson control, robot
control, camera stream, analytics, history, reports) require login at `/login`.
Default account: **teacher / teach123** (seeded on first run; passwords are
stored salted + hashed). Change it with `POST /api/auth/change-password`.
Student, robot and projector screens stay open on the local network.

### Theme

All pages use a **white (light) theme by default**; a floating moon/sun button
(bottom-right) switches to dark mode and remembers the choice per device. The
robot face page always stays dark - it is the robot's screen.

## Run it with Docker (any device)

One-time: install [Docker Desktop](https://www.docker.com/products/docker-desktop/)
(macOS/Windows) or Docker Engine (Linux). Then, from this folder:

```bash
CAT_PUBLIC_HOST=<your-LAN-IP> docker compose up -d
```

That starts two containers: the CAT app (port 8000) and Ollama (the offline
LLM; `llama3.2:3b` is pulled automatically into a volume on first start).
The neural voice model downloads itself on first run. Open
`http://localhost:8000` - students on the same Wi-Fi use
`http://<your-LAN-IP>:8000/student` (that's why `CAT_PUBLIC_HOST` matters for
the QR codes).

Differences inside Docker:
- **Robot voice** plays from the robot-face page in the browser (containers
  have no host speakers) - same natural neural voice, streamed via `/api/tts`.
- **Camera mode** isn't available (containers can't reach the webcam); the
  perception system runs in simulation mode.
- Data (database, uploaded lessons/PDFs, voice model) persists in the
  `cat_data` volume; LLM models persist in `ollama_models`.

Useful commands: `docker compose logs -f cat` (logs),
`docker compose down` (stop), `docker compose build cat` (rebuild after edits),
`docker compose exec ollama ollama pull llama3.2:1b` (extra models).

## Run it

```bash
./run.sh
```

or manually:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

In VS Code: open this folder, then **Run > Start Debugging** ("Run CAT server"),
or **Terminal > Run Task > Run CAT server**.

## 2-minute demo

1. Open **/teacher**, pick a lesson, press **Start**.
2. Open **/robot** (tap to enable the voice) and **/projector** in other windows.
3. On phones/tablets on the same Wi-Fi, scan the QR (or open the student URL),
   enter a name, pick a seat, **Join** (or open several `/student` tabs to simulate
   a class).
4. Press **Next** to step through content and questions. Watch answers and
   engagement scores update live.
5. Press **End**, then review the session in the tracking page's Sessions tab.

## Project layout

```
backend/
  main.py           FastAPI app, REST + WebSocket, robot behavior loop
  lesson_engine.py  Lesson state machine (questions, timers, mini-game, scoring)
  analytics.py      Engagement scores (1/4 A+P+Q+S), alerts, history
  perception.py     Simulated vision/audio localization (+ optional OpenCV)
  llm.py            Constrained LLM/NLU over the lesson knowledge base
  database.py       SQLite storage
  lessons/          Lesson scripts (math_puzzle.json, science_quiz.json)
frontend/
  index.html        Landing page + QR
  teacher.html      Teacher dashboard
  tracking.html     Student tracking (live + history)
  student.html      Student response app
  robot.html        Robot face + TTS
  projector.html    Big-screen view
  static/           Shared CSS/JS (no external libraries - fully offline)
data/               SQLite database (created at runtime)
```
